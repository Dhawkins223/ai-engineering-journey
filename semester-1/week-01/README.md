# Week 1 - Python + Git + Shell Basics

**Official week:** September 15 to September 21, 2026  
**Target:** 30 productive hours across Tuesday through Sunday  
**Monday:** fixed rest day

The 30-hour target is retained because it is the only explicit weekly capacity currently declared in the curriculum. If a different realistic weekly capacity is set, rescale the blocks instead of increasing daily workload.

## Academic honesty boundary

All official CS50 assessment code stays in **cs50.dev**.

Do not copy CS50 problem-set code into this public repository, even after submission.

This repository contains only original non-CS50 work, notes, curriculum files, and tooling.

For CS50 assessments:

- use https://cs50.dev/
- follow https://cs50.harvard.edu/python/honesty/
- do not use ChatGPT, Claude, Copilot, Gemini, or other external AI systems to suggest or complete answers or lines of code
- use CS50's own AI tools only where the course permits them
- do not publish assessment solutions

## Learning objectives

By the end of Week 1, be able to:

- write small original Python programs without copying a tutorial
- use variables and basic data types
- use input() and print()
- write and call functions with parameters and return values
- use if, elif, and else
- use comparison and Boolean operators
- read and investigate a basic Python traceback
- use a basic Unix shell
- use git clone, git status, git add, git commit, git push, and git log
- push original non-CS50 code to GitHub and explain it line by line

## Debugging block

Week 1 includes a dedicated traceback/debugging block.

Reference:

https://docs.python.org/3/tutorial/errors.html

Practice only with original non-CS50 code.

The block is complete when you can:

- intentionally create a simple error in your own program
- identify the last relevant line in the traceback
- name the exception type
- explain the likely cause
- fix the problem and rerun the program

## Time-block rule

Every time block in the PDF has a "done when" condition.

The minutes are estimates.

- Finish early: move to the next block.
- Run long: stop at a sensible checkpoint, record the blocker, and roll the unfinished work forward.
- Do not use Monday as catch-up.
- Do not add hours just to preserve the calendar.

## Monday rule

Monday is a fixed rest day.

If unfinished work remains on Sunday night, it rolls into Week 2 before new Week 2 material.

## Completion gate

Week 1 is complete when all of the following are true:

1. A small original Python program can be written independently.
2. Variables, types, functions, parameters, arguments, and return values can be explained.
3. Basic conditionals can be used correctly.
4. A basic Python traceback can be investigated.
5. Basic shell navigation can be used.
6. clone, status, add, commit, push, and log can be used for original repository work.
7. At least one original non-CS50 Python program exists in this repository and can be explained line by line.
8. No CS50 assessment code was committed to this repository.
9. Monday remained a rest day.
